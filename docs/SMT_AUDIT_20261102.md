# SMT investigation — 2026-11-02

**Follow-up:** The confirmed session interpretation, pending-history retry and diagnostic-label defects were subsequently repaired. See [the repair and validation record](SMT_SESSION_REPAIR.md). The findings below document the original build; older historical-session uncertainty remains explicitly covered in the repair limitations.

## Confirmed blocker

Live logs from the user's MetaQuotes-Demo XAUUSD terminal report `SMT_TREND_NEUTRAL` while the details say `TREND=INSUFFICIENT_DATA` and frequently `CONTEXT=INSUFFICIENT_DATA`. The all-five preset uses strict D1 trend, H4 context/primary zones, H1 secondary zones, M15 traps and M5 entry confirmation. An insufficient D1 trend blocks entries even when context alignment is disabled.

A read-only native script in an isolated portable MT5 instance reproduced the issue using the same demo server and XAUUSD history. It did not initialize the production EA or submit any orders. It loaded 300 completed D1 candles from 2025-09-03 through 2026-10-30 with the history series synchronized. The production history/trend code still returned insufficient data.

The server's raw weekly session metadata was:

| Day | Start seconds | End seconds |
|---|---:|---:|
| Monday–Friday | 0 | 82800 (23:00) |
| Saturday | 0 | 0 |
| Sunday | no session row | no session row |

`SBSession` reduces endpoints modulo 86400 and treats equal start/end as a full-day session. That conflates a zero-duration `0–0` row with a genuine full-day `0–86400` row. Saturday is consequently classified as tradable. `SBSMTGapAllowed` probes missing candle intervals using this shared helper and rejects normal weekend gaps. The diagnostic recorded **62 D1 resets**, **10 H4 resets**, **9 H1 resets** and **1 M15 reset** in the respective 300-bar samples. Resets erase the confirmed swing counts needed to classify trend. D1 history loading additionally fails the weekend staleness/gap check.

This is a code defect in session interpretation, not evidence that the symbol lacks 300 D1 candles or that its actual market trend is neutral. The same session helper is shared with other runtime checks, so its correction should preserve genuine full-day and overnight sessions and be regression tested across strategies.

## Separate historical-session limitation

The H1 sample also contains older weekday gaps around midnight, for example 2026-10-14 22:00 to 2026-10-15 01:00. Today's reported weekday schedule classifies 00:30 as tradable, causing another reset. Current weekly broker metadata alone does not establish whether an older gap was a scheduled historical closure or missing data. Holiday gaps also require historical evidence. The investigation does not assume either explanation, disable gap checks, or infer historical schedules from today's clock.

## Diagnostics and other observations

- `SMT_TREND_NEUTRAL` currently labels both genuinely neutral trend and insufficient history. Those reasons should be distinguished in a repair.
- `SBSMTCheckTrap` advances `last_trap` before loading the required zone context. If that context load fails, the same trap is not retried. This is a source-level missed-opportunity risk; the live logs show history-pending events, but this investigation does not establish that a particular valid trade was missed because of it.
- Confirmation dispatch is synchronous when SMT reaches READY. This review did not find an added order-submission candle wait.
- Fresh-zone, trap, subsequent CHoCH/BOS, target geometry, position, spread and risk checks continue to apply. Existing synthetic SMT fixtures passed 107 checks in the previous timing audit; those passes did not cover this actual zero-duration Saturday session row and therefore did not rule out this failure.
