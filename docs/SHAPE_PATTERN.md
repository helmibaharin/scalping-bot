# Shape Pattern Strategy: research implementation

## Audit and compatibility

Before this change the repository contained implemented 4H reversal, Triangle continuation, ORB continuation/false-breakout and two SMT profiles. Triangle was a single-timeframe, three-subtype detector. Shared account risk, hedging ownership and netting collision protection existed. Deal CSVs existed, but detailed attribution depended partly on comments; original planned risk was not durably associated with every position.

Strategy 2 now has stable identity `S2_SHAPE_PATTERN`. The internal enum `SB_TRIANGLE=2`, `InpEnableTriangleMethod`, `InpTriangleMagicNumber`, risk limits, pivot/touch/geometry inputs and `TRIANGLE` chart namespace remain compatibility aliases. The original Triangle detector/runtime remain available through `InpShapeLegacyTriangle=true`. All six historical profiles explicitly select that mode; every prior input value remains identical. External saved profiles should append that input before loading this expanded build if they must retain their original decisions. Omitted new inputs use new Shape defaults, so review imported profiles explicitly.

`profiles/shape-m15-m5-demo.set` selects the new engine, all eight families and both methods. It disables other strategies for isolated research. The master switch is still `InpEnableTriangleMethod`. It uses a separate magic namespace, signal-only, real-account denial and unverified broker-clock defaults. To compare all strategies on a hedging demo, independently enable each and assign noncolliding magic numbers; both SMT profiles require separate chart instances with their supplied distinct magic namespaces. Shared account caps still apply; they can block otherwise independent entries. A netting account rejects occupied-symbol entries rather than merging attribution.

## Deterministic formation rules

M15 formation, M5 entry and optional H1 context are configurable. Only completed candles enter caches. Strict left/right pivots reject equal adjacent extrema and record pivot time, price, side and actual confirmation close. Each pattern records the exact confirmed pivot payload. Equality of separated confirmed pivots is allowed within max(point tolerance, ATR fraction). ATR is a bounded 14-bar true-range mean, calculated without indicator handles. Missing contiguous formation/entry data invalidate pending candidates.

| Family/subtype | Geometry | Continuation direction/target |
|---|---|---|
| Ascending triangle | Flat upper, rising lower, converging width | Either qualified break; legacy configured fixed RR |
| Descending triangle | Falling upper, flat lower, converging width | Either qualified break; legacy configured fixed RR |
| Symmetrical triangle | Falling upper, rising lower | Either qualified break; legacy configured fixed RR |
| Bullish/bearish flag | Parallel countertrend/flat channel; preceding 4–12-bar directional impulse at least configured ATR multiple; channel width at most pole fraction | Pole direction; measured pole from breakout |
| Head and shoulders / inverse | Ordered shoulder–neck–head–neck–shoulder pivots; head prominence, shoulder-height and time-symmetry limits | Neckline break; head-to-neck measured distance |
| Double top / bottom | Two equal-within-tolerance extrema separated by meaningful opposite pivot | Neckline break; extrema-to-neck distance |
| Falling wedge | Both lines falling, upper falling faster; converging width | Bullish; initial width from breakout |
| Rising wedge | Both lines rising, lower rising faster; converging width | Bearish; initial width from breakout |

Channels require configured confirmed touches on each line and wick containment within tolerance. Triangle/wedge width, duration, convergence and future apex limits apply. Neckline patterns reject prior closing neckline breaks during formation. Flags record both pole endpoint candles and prices. Detection considers eight recent pivot endpoints across eleven subtypes within the bounded lookback, rather than searching all combinatorial pivot selections. Consequently this is a conservative, specified detector, not an exhaustive chart-pattern recognizer.

Candidates have fixed formation lines. They are not refitted after detection. IDs include symbol, formation timeframe, subtype and anchor times. Identical IDs and overlapping same-family/same-direction near-identical boundaries are suppressed; independent intervals/families remain separate. Capacity is bounded. Consumption survives restart through terminal globals and the lifecycle ledger; replay retires historical confirmations without chasing them.

## Entry sequences

Continuation requires a new completed close crossing the relevant boundary with a directional body and minimum ATR displacement. The next qualifying retest records a protective extreme. A separate later completed candle must preserve that extreme and confirm continuation. SL is beyond the retest swing plus the existing Strategy 2 protective buffer. Triangle retains fixed configured RR and its existing fill-RR repair policy; other families use the table's measured targets and must not move them farther after filling. The continuation price-RR minimum applies at executable prices. Structural target methods also require the cost-adjusted minimum; the legacy fixed-RR policy retains its existing deviation-based risk sizing rather than applying an incompatible extra cost-RR threshold.

Shared `LiquiditySweep.mqh` classifies `NO_TRAP_DETECTED`, `POSSIBLE_SWEEP`, `SWEEP_REENTRY_CONFIRMED`, `BREAKOUT_HOLDING`, `BREAKOUT_FAILED`, `INSUFFICIENT_DATA`. It uses a reference known before the decision candle opened. Wick reentry and delayed closing failures retain the complete excursion extreme. Simultaneous upper/lower excursions are rejected because OHLC cannot prove their sequence. This utility is available to other strategies without changing their decisions.

An upper trap proposes SELL; a lower trap proposes BUY. Trap confirmation cancels continuation and freezes the excursion extreme. An opposing established local trend requires CHoCH first. Subsequent BOS must break a distinct pivot formed and confirmed after CHoCH, on a later candle. Without meaningful opposing structure, CHoCH is N/A but a later directional BOS is mandatory. The trap candle cannot confirm either sequence. Swing breaks use completed closes and pivots known before that candle opened.

The reversal SL stays beyond the frozen extreme plus buffer. A breach, reestablished original breakout, failed CHoCH, crossed pattern geometry, age/confirmation expiry, missing data or consumed execution retires the candidate. No SL tightening is used to improve RR. One candidate can execute only one branch.

Reversal targets are the nearest currently unbroken confirmed opposing swing/equal high or low, pattern support/resistance or neckline, optionally including H1 confirmed structure. TP is buffered before that level and rounded inward. These are structural support/resistance references, not SMT strong-zone classifications. No reference means no trade. An inadequate nearest target rejects the entry; farther targets are never substituted to manufacture RR. The optional minimum starts at 1R and includes configured commission/deviation allowance in execution checks.

Risk blocks are recorded as `BLOCKED` with exact reason. Spread, margin, permissions and account caps are temporary account/quote conditions; malformed geometry, missing target and invalid RR are permanent setup failures. Both retire that confirmation under the existing no-chase policy; a temporary block does not authorize a delayed entry from an old signal.

## Durable attribution and reports

Every new request writes and flushes a versioned `*_lifecycle.csv` snapshot **before** `OrderSend`. The UID combines login, symbol, magic, signal ID and signal candle. Snapshots carry stable strategy/profile, family/subtype/method, exact pivots, boundaries/liquidity, trap/CHoCH/BOS times/status, geometry, original requested risk/volume and RR. Order results associate broker order tickets; accepted requests are not fabricated fills. `OnTradeTransaction` associates actual broker deals and position identifiers through order/position relations; broker comments may change without losing these associations. History reconciliation deduplicates deal tickets after restart.

The journal is mandatory even when optional diagnostic CSV logging is disabled. Live journals are appended, not erased on initialization. Copy them with the EA when migrating terminals. A malformed/torn journal fails initialization. A crash between send and result is recovered only when history has exactly one matching order by symbol, magic, side, volume and a ten-second request window; zero/ambiguous matches lock for manual broker review rather than guessing. Existing pre-journal trades retain legacy deal reporting and are not assigned invented family/method metadata. Terminal-global consumption remains an additional safeguard.

Run `python tests/report_lifecycle.py <one-or-more-live-lifecycle.csv> --output <directory>` for JSON, CSV and Markdown reports. Analyze independent Strategy Tester runs separately: their account/ticket namespaces may be reused. Reports always contain five stable strategy groups and every Shape family, subtype, method and family+method combination, including empty groups. Rejected signals count unique execution `ENTRY_REJECT`/`ORDER_CHECK_REJECT` records; pre-entry pattern invalidations and context disqualifications remain separately traceable state events. Wins/losses/breakeven use net P&L; gross profit/loss and PF use gross trading P&L before fees. Net includes all available commissions, swap and fees. Completed trades are balanced positions, not deals; partial fills/closes and replay duplicates count once. Unknown/incomplete or mixed netting positions are excluded and listed explicitly.

Realized R = complete-position actual net P&L / original requested monetary risk frozen before send. Partially filled requests keep that original denominator, conservatively including unfilled requested volume; one denominator per unique signal is counted, never once per fill. Slippage uses actual entry deals and requested entry. Drawdown is reconstructed closed-position net cash, **not** account floating equity drawdown. The native tester report separately supplies actual simulated account equity drawdown. Missing fills/metrics remain unavailable. Old `analyze_backtests.py` remains a historical compatibility analyzer; new lifecycle reports are authoritative for detailed attribution.

## Installation and validation

No automatic live deployment is performed. Compile locally with `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scalping-bot/compile.ps1`, or manually copy the project `MQL5/Include/ScalpingBot` and `MQL5/Experts/ScalpingBot.mq5` into a chosen demo terminal and press F7 in MetaEditor. Keep CapitalGuard separate. Load the explicit legacy profile or the new Shape profile, verify broker UTC/DST mapping, use signal-only first, and inspect logs/chart labels before enabling demo order execution.

Tests: `test_rules.ps1`, `test_risk_execution.ps1`, `verify_project.ps1`, Python `test_analyzer.py`/`test_lifecycle_report.py`, native `ORBTests.mq5`, `SMTTests.mq5`, `ShapeTests.mq5`, and tester-only `LifecycleTests.mq5`. The lifecycle fixture deliberately sends one tiny **simulated** position and two closes to exercise actual callbacks; it refuses initialization outside Strategy Tester. Offline partial-fill fixtures complement native partial-close checks. Compile fixtures through `compile.ps1 -Source ...`.

`tests/prepare_shape_backtests.ps1` and `tests/run_backtests.ps1` create isolated portable tester scenarios for native fixtures, legacy regressions, both Shape methods separately/together and all-strategy comparison on EURUSD/XAUUSD. Raw logs, exact inputs, hashes and native reports are retained outside the disposable cache. UTC+3 is an explicit historical test assumption, not live broker verification. Extend real-tick samples across many sessions, volatility regimes and instruments; inspect spread/fees/execution delays, stop rules, pattern false positives, both branch confirmations, restart during outstanding orders and risk-cap interference. Use chronological development/holdout periods and no parameter selection on the final holdout. Unit/smoke tests do not establish profitability or production readiness.
